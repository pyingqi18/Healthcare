1. 文件夹用途
config保存研究参数、地区定义、类别规则和人工审核决定。
2. settings.yaml
保存数据目录、DataForSEO非敏感参数、面板截止年份和抓取批量。正式模型细节不再重复写在这里，只通过`analysis.contract`指向`config/final\_analysis.yaml`
3. final\_analysis.yaml
冻结完整重抓前的正式分析协议。2015至2025年分析期、2-mile上年进入冲击、竞争密度、clinic与market-year fixed effects、共同样本以及哪些空间方法属于稳健性或探索性分析。
4. pipeline.yaml
保存统一运行入口的profile、阶段顺序、输入、输出和命令。corrected\_v1\_audit可以执行；full\_rebuild在全市场抓取和最终exposure构建完成前保持blocked。
付费任务数量已经改为从manifest和task log推导，raw与interim目录由run name统一生成。full\_rebuild当前剩余阻塞项是全市场搜索范围、run-specific人工决定、替换逻辑和最终exposure builder。
5. regions.yaml
保存当前15个研究市场的州、规模、ZIP范围、中心坐标和DataForSEO location code。这里的location code表示搜索位置，不等于商家地址一定在目标ZIP，所以抓回来的候选还要单独做ZIP资格检查
6. 类别文件
provider\_taxonomy.csv和google\_category\_rules.csv保存哪些类别属于牙科、哪些需要人工审核、哪些应排除。
7. 人工决定
candidate\_manual\_decisions\_20260908.csv保存候选资格决定。
profile\_resolution\_decisions\_20260910.csv和location\_group\_decisions\_20260910.csv保存资料排除和实体地点归并决定。
8. 修改规则
如果只是某一条人工判断需要改变，就改对应决定文件并重跑下游步骤，不直接改脚本生成的CSV。年份、主exposure、fixed effects这类研究设计改变则必须修改`final\_analysis.yaml`，同时在报告里说明为什么改变以及改变发生在看结果之前还是之后。账号和API password不属于config内容，只能放在本地环境变量里。
9. scrape_plans.yaml
保存原15市场的只规划抓取profile、旧53组合方案的对照任务数、分阶段新搜索方案和带核验日期的价格参数。该profile明确设置execution_enabled为false，只能计算任务量和费用区间，不能提交API。
10. business_listings_dental_categories.csv
google_dental_category_groups.csv将Google返回的13个牙科类别映射到legacy的General、Special和Surgery三组。映射读取category和additional_categories证据，不根据本次使用的搜索关键词直接分类；同时出现多组证据时按Surgery、Special、General顺序保留更具体的组。
11. settings.yaml中的business_listings_live endpoint供两市场Live试验执行器使用；账号密码仍只从环境变量读取。
Maps Standard补抓同时登记maps_post、maps_tasks_ready和maps_get。提交、完成检查与结果下载使用三个不同入口；tasks_ready检查和结果GET不产生新的抓取任务。
12. business_listings_pilot_candidate_decisions_20260918.csv分别记录人工候选是否进入竞争地点集合和评分profile集合；business_listings_pilot_reference_decisions_20260918.csv分别记录旧地点是否进入当前召回率分母和是否保留在历史面板。
保存从DataForSEO 2026-09-01官方Business Listings类别快照中核对出的13个研究纳入类别、全球business count、Google展示名称和研究决定。接口类别名必须与官方目录精确一致，不能从展示名称自行推断。
13. business_listings_pilot_location_decisions_20260919.csv记录14个complex或focused block的竞争地点决定、canonical描述profile、证据类型和证据来源。该文件只决定竞争计数单位，不授权合并rating历史。
14. business_listings_pilot_carry_forward_locations_20260919.csv记录Business Listings未发现但人工证据确认仍在营业的旧地点。Hybridge的地址和当前电话来自官网，坐标来自corrected_v1 legacy crosswalk；旧电话不继续作为当前字段使用。

15. settings.yaml中的business_listings_available_filters是官方非任务GET端点，只用于核对当前可过滤字段。它不替代付费search/live端点，也不能在未检查返回目录前假定ZIP字段可以服务端过滤。

16. scrape_plans.yaml中的major_metro_target_zip_regex冻结NYC和LA的服务端ZIP过滤表达式。代码要求正则在全部00000至99999五位值上与regions.yaml完全一致，不能为了减少结果量临时缩小市场。
17. scrape_plans.yaml中的business_listings_rollout保留原15个研究市场及分阶段抓取边界。Malone和Syracuse使用pilot，Atlanta使用大型市场验证，10个普通市场使用standard rollout，纽约和洛杉矶使用ZIP过滤后的完整分页结果。已经完成的阶段仍保留原manifest和费用记录，不能因为后续审核而改写。

18. identity_rule_manual_decisions_20260919.csv保存31a生成的22条放宽身份规则候选的逐条证据决定。其中20条确认属于同一历史地点，2条旧记录超出牙科竞争样本范围。该文件只授权这些reference_key进入召回率重算，不授权将候选规则推广到其他记录，也不合并rating profile。

19. profile_eligibility_verified_decisions_20260925.csv冻结阶段46i结束时已经完成的251条profile资格决定。profile_eligibility_remaining_decisions_20260925_partial.csv保留阶段46j的历史工作检查点，不作为最终输入。当前最终路径由46m把这251条基线与用户本地生成的199条`remaining_profile_verified_additions.csv`合并，要求450条总量、217条纳入、233条排除和0条未决。

20. settings.yaml中的review_depth_maximum为4490，供full rebuild逐outcome profile评论采集使用。达到该深度但returned unique review ID仍少于reported reviews count时，审计保留左截断状态，不允许把Business Listings aggregate rating或同一physical location的其他profile评论补作该profile历史。
